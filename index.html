Scenario 01

Basic CI Pipeline

Run tests automatically on push and pull requests to ensure code quality.


on:
  push:
    branches: [ "main" ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm install
      - run: npm test
Scenario 02

Scheduled Jobs (Cron)

Run tasks at specific times, like daily database backups or nightly builds.


on:
  schedule:
    - cron: '0 12 * * *' # Every day at 12 PM UTC

jobs:
  daily-backup:
    runs-on: ubuntu-latest
    steps:
      - run: ./run_backup.sh
Scenario 03

Manual Trigger

Allow developers to trigger workflows from the UI and pass custom inputs.


on:
  workflow_dispatch:
    inputs:
      env:
        description: 'Target Environment'
        default: 'staging'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploying to ${{ inputs.env }}"
Scenario 04

Matrix Strategy

Test your code simultaneously across different operating systems and languages.


jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
        node: [18, 20]
    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
Scenario 05

Issue Management

Automate community engagement by acting on GitHub events (e.g., Issue opened).


on:
  issues:
    types: [opened]

jobs:
  welcome:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: "Thanks for the issue!"
            })
Scenario 06

Docker Build & Publish

Automate your container lifecycle. Build and push to DockerHub on new tags.


steps:
  - uses: docker/login-action@v3
    with:
      username: ${{ secrets.DOCKER_USER }}
      password: ${{ secrets.DOCKER_PAT }}
  - uses: docker/build-push-action@v5
    with:
      push: true
      tags: user/app:${{ github.ref_name }}
Scenario 07

Reusable Workflows

DRY (Don't Repeat Yourself). Create templates to share across multiple repositories.


# In the Caller Workflow:
jobs:
  call-template:
    uses: ./.github/workflows/template.yml
    with:
      config: 'prod'
    secrets:
      token: ${{ secrets.GITHUB_TOKEN }}
Scenario 08

Contexts & Expressions

Dynamically control your workflows using conditional logic and GitHub contexts.


jobs:
  conditional-job:
    runs-on: ubuntu-latest
    steps:
      - name: Run only if branch is main
        if: github.ref == 'refs/heads/main'
        run: echo "Production Deploy!"
Scenario 09

Artifacts

Pass files (like build binaries or test reports) between jobs.


- uses: actions/upload-artifact@v4
  with:
    name: build-output
    path: dist/
    
# In a later job:
- uses: actions/download-artifact@v4
  with:
    name: build-output
Scenario 10

Environment Vars & Secrets

Securely inject API keys, passwords, and environment data.


env:
  GLOBAL_VAR: "Hello"
  
jobs:
  job1:
    runs-on: ubuntu-latest
    steps:
      - run: curl -H "Auth: ${{ secrets.API_KEY }}"
Scenario 11

Dependency Caching

Speed up your pipelines by caching massive dependency directories.


- uses: actions/cache@v4
  with:
    path: ~/.npm
    key: ${{ runner.os }}-node-${{ hashFiles('package-lock.json') }}
    restore-keys: |
      ${{ runner.os }}-node-
Scenario 12

Auto Create Release

Draft and publish GitHub Releases automatically when tags are pushed.


- uses: softprops/action-gh-release@v2
  with:
    generate_release_notes: true
    draft: false
Scenario 13

Auto Approve & Merge

Approve Dependabot PRs instantly to keep dependencies up-to-date.


- uses: hmarr/auto-approve-action@v4
  if: github.actor == 'dependabot[bot]'
  
- run: gh pr merge --auto --merge "$PR_URL"
  env:
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
