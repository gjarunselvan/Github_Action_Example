Scenario 01

Basic CI Pipeline

Automatically run your test suite every time code is pushed or a Pull Request is opened.

  • Ensures code quality
  • Prevents broken builds in main
  • Provides immediate developer feedback

on:
  push:
    branches: [ "main" ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm install
      - run: npm test
Scenario 02

Scheduled Jobs (Cron)

Automate repetitive tasks that need to run at specific times.


on:
  schedule:
    # Runs every day at 12 PM UTC
    - cron: '0 12 * * *' 

jobs:
  daily-backup:
    runs-on: ubuntu-latest
    steps:
      - run: ./scripts/run_backup.sh
      - run: echo "Backup completed successfully!"
Scenario 03

Manual Trigger

Use workflow_dispatch to give your team a beautiful UI to trigger deployments or maintenance scripts on-demand.


on:
  workflow_dispatch:
    inputs:
      env:
        description: 'Target Environment'
        required: true
        default: 'staging'
        type: choice
        options: [staging, production]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploying to ${{ inputs.env }}!"
Scenario 04

Matrix Strategy

Multiply your productivity. Test your application across multiple operating systems and language versions in parallel.


jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
        node: [18, 20]
    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
Scenario 06

Docker Build & Publish

Automate your container lifecycle. Build your images and push them to DockerHub or AWS ECR seamlessly when tags are created.


steps:
  - name: Login to DockerHub
    uses: docker/login-action@v3
    with:
      username: ${{ secrets.DOCKER_USER }}
      password: ${{ secrets.DOCKER_PAT }}
      
  - name: Build and Push
    uses: docker/build-push-action@v5
    with:
      push: true
      tags: myorg/myapp:${{ github.ref_name }}
Scenario 10

Environments & Secrets

Securely inject API keys, cloud credentials, and dynamic environment variables without exposing them in your code.


env:
  GLOBAL_VAR: "Hello from Global"
  
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Call API
        run: curl -H "Auth: Bearer ${{ secrets.PROD_API_KEY }}" https://api.com
        
      - name: Login to Cloud
        run: az login --service-principal -u ${{ secrets.APP_ID }} -p ${{ secrets.PASS }}
Scenario 11

Dependency Caching

Drastically reduce your build times by caching large directories (like node_modules or .m2) across different workflow runs.


- uses: actions/cache@v4
  with:
    path: ~/.npm
    key: npm-${{ hashFiles('package-lock.json') }}
    restore-keys: |
      npm-
